# 听剧统计 · 档案柜

从 Notion 搬过来的广播剧听剧管理站，接了猫耳 FM 的已购和追剧同步。

**视觉基调**：羊皮纸色桌面上摊开档案夹，夹子里塞着瓷白卡片。侧栏是一摞磁带脊背，
每组一个色带，选中的那盘往右抽出来。

三层底色必须拉开，这是「卡片跟背景格格不入」的解法：
`parchment #f4f3ee`（桌面）→ `antique-white #f7eada`（夹子）→ `porcelain #fffbf6`（卡片）。
`raspberry #e31258` 是唯一的高饱和色，只给「选中 / 当前」用 —— 铺开就压过封面，
而封面才是这个站的主角。六个收听状态各有自己的颜色，这是页面不至于单调的地方。

```bash
npm install
npm run dev          # http://localhost:5273
```

前端 Vite + React + TS（5273），后端 Express + SQLite（5174，vite 代理转发）。

## 分类模型：挑出来的 ≠ 库里的

这是整站的组织原则。同一批剧，「你挑出来准备做的」和「堆在库里的」是两层，
导航也按这个分：

| 短名单（每天看） | 库存（隔段时间翻） |
|---|---|
| **在听** — 正在听的 | **囤着** — 买了还没开始 |
| **想听** — 从库里挑出来准备接下来听的 | **剧集库** — 全部 |
| **重刷计划** — 挑出来准备重刷、还没开始的 | **重刷库** — 已经刷过几遍的历史 |

收听状态六个值，关键是这三个的区别：

- **想听** — 主动挑出来排进队列的
- **囤着** — 买了放着，还没打算动
- **搁置** — 已经听了一部分，停下了

（另外三个是 在听 / 听完 / 弃了。）

「重刷计划」和「重刷库」在数据上也是两列：`rewatch_queued` 是布尔的计划标记，
`rewatch_status` 是「已二刷/已四刷」的历史。Notion 原来把「待重刷」和「已n刷」
混在同一列里，语义上不是一回事。

## 核心约定：手动优先

**你的标记永远是真值，猫耳只是参考。** 这条贯穿整个数据模型：

| 字段 | 同步行为 |
|---|---|
| 收听状态 / 已听集数 / 评分 / 听完日期 / 重刷状态 / 剧评 | **永不覆盖** |
| 是否购买 | 只升不降（未购→已购 采用；已购→未购 只提示）<sup>1</sup> |
| 是否追剧 | 直接采用猫耳 |
| 总集数 / 分类 / 社团 / 封面 / 价格 / 连载状态 / 简介 | **空缺才回填**，你填过就不动 |
| 猫耳的上次收听位置 | 只写 `sync_saw_episode` 快照，在 UI 上作为「猫耳停在第 X 集」的灰色提示出现，绝不进主字段 |

<sup>1</sup> 猫耳支持单集购买，整剧不在已购列表不代表没花过钱。《沉浮事》就是这种情况。

**漫播和其他平台的剧完全不参与同步**，只能手动录入和编辑（剧集库 → `+ 手动录入`）。

## 三个数据管道

### 1. Notion 导入（一次性）

```bash
npm run import:notion            # 默认读 notion-export/unpacked/
```

Notion 导出的是**双层 zip**，外层文件甚至没有 `.zip` 后缀，且 macOS 自带 `unzip`
不认 UTF-8 文件名（中文目录会解压出 0 个文件）。正确姿势：

```bash
cd notion-export
ditto -x -k notion unpacked                    # 外层
cd unpacked && ditto -x -k ExportBlock-*.zip . # 内层
```

导入器会把主库 CSV、每部剧 `.md` 里的剧评正文、以及本地封面图一起搬进来。
**已知缺口**：Notion 导出漏打包了 2 张本地封面（《殿下让我还他清誉 第一季》
《皇恩浩荡》），CSV 里有引用但文件不存在，需要手动补。

### 使用路径

```
猫耳同步 → 「待整理」批量给状态 → 日常只看「在听」+ 本周哪天更新
        → 听完写 repo → 生成分享长图
```

- **不显示「落后几集」**。卡片上只有磁带进度条和「听到哪 / 共几集」。
- **追剧页按买没买分两栏**：已购的可以直接安排，只追没买的是待决策。
- **筛选项全部自动生成**（`/api/facets`）—— 状态、平台、题材、主役 CV、社团、
  年份、评分都是从你的数据里数出来的，不维护任何硬编码枚举。
- **分享长图**：详情页「生成分享长图」，canvas 手绘出封面 / 剧名 / CV / 评分 /
  repo 全文，高度按正文实际行数算，长文不会被截断。
- **封面统一 1:1**：远程封面居中裁，也可以自己上传 —— 上传时在浏览器里就裁成
  640×640 再传，所以服务端不需要图像库，尺寸绝对统一。

### 2. 猫耳同步（可重复跑）

**关键分界：只有「已购 / 追剧」两个列表需要登录态，剧集详情是公开接口。**
所以浏览器只干最少的活，几百次详情请求全在服务端跑。

**日常就点侧栏的「自动更新」**。第一次要贴一段 cookie（见下），之后每次同步
就是一个按钮：拉列表 → 合并标记 → 补详情 → 缓存封面，全在服务端跑，
面板里有实时日志，关掉窗口任务照常继续。

命令行等价物：

```bash
# ① 浏览器：Chrome 打开 https://www.missevan.com/ 确认已登录，
#    F12 → Console 粘贴 tools/export-missevan.js，
#    下载到的 missevan-lists.json 放进 data/
npm run import:missevan     # ② 合并已购 / 追剧标记
npm run fetch:details       # ③ 补 CV / 分类 / 社团 / 集数（服务端直连，不用登录）
npm run cache:covers        # ④ 预热封面
```

### 登录态

「已购 / 追剧」两个接口要登录态，而猫耳站点的 CSP 挡死了从它页面直接把数据
POST 回本地。所以做法是把 cookie 存在本机：

- 存在 `data/.missevan-session.json`，**600 权限、已进 .gitignore**
- 存之前先拿它调一次已购接口验证，验不过不存
- `GET /api/sync/session` 只回「有没有 / 是谁」，**从不回传 cookie 本身**
- 会过期。过期时猫耳返回的是登录页 HTML 而不是 401，所以
  `fetch-lists.mjs` 显式检查「两个列表都空」并以退出码 3 结束 ——
  同步会明确报「登录态过期」，**不会静默同步出一份空数据**

不想存 cookie 的话，面板里手动上传 `missevan-lists.json` 的老路子还留着，
`tools/export-missevan.js` 也还在。

| 用途 | 接口 | 要登录吗 |
|---|---|---|
| 我的已购 | `GET /mperson/getdramabought?page=N&page_size=100` | 要 |
| 我的追剧 | `GET /dramaapi/getusersubscriptions?user_id=X&page_size=20&page=N` | 要 |
| 剧集详情 | `GET /dramaapi/getdrama?drama_id=X` | **不要** |

几个踩过的坑：

- ⚠️ **追剧接口的翻页参数是 `page`，不是页面 URL 里那个 `p`。** 传 `p` 会静默
  返回第一页 —— 会出现「抓了 15 页、其实全是同 20 条」。
- CV 名字嵌在 `cvs[].cv_info.name` 里，顶层没有 `name` 字段。
- 下架的旧版剧（标题带「（旧）」）详情接口返回 403，需要登录态才拿得到，
  目前有 6 部这样的剧缺 CV 和封面。
- **别指望从 missevan.com 的页面直接 POST 到 localhost** —— 站点 CSP 会拦掉
  `connect-src`，`fetch` 和 `sendBeacon` 都到不了。所以走的是「下载文件 → 导入」。
  Chrome 还会拦同一站点的连续自动下载，被拦时地址栏右侧有提示，点开允许即可；
  实在不行用 `copy(JSON.stringify(window.__missevanLists))` 手动粘贴。

接口变了的话，[`tools/discover-missevan-api.js`](tools/discover-missevan-api.js)
可以重新探测：贴进 Console，点几下页面，`__me.dump()` 导出接口清单。

### 3. 封面缓存

```bash
npm run cache:covers
```

猫耳 CDN 校验 Referer，浏览器直连图片一律 **403**。所以远程封面统一走
`/api/cover` 代理（带 Referer 回源）并落盘到 `data/covers/remote/`。
不预热的话第一次打开要现抓三百多张图。顺带好处：猫耳换图删图后本地这份还在。

## 框架

整站从猫耳的两类数据长出来，侧栏 8 格：

| 组 | 页面 | 说明 |
|---|---|---|
| **猫耳** | ① 我的已购 | 花过钱的。**卡片上直接点状态就能标**，默认「未标记」排最前 |
| | ② 我的收藏 | 追了但没买的，观望中。买了之后同步会自动挪进 ① |
| **在听** | ③ 正在听 | `status=在听` + 本周更新日历（周一到周日，只排在听的） |
| | ④ 重刷 | 「计划」= 挑出来还没开始的；「库」= 刷过几遍的历史 |
| **回顾** | ⑤ 听完的剧 | 近 30/90 天 + 按年份切换的可视化年报 |
| | ⑥ 剧单榜单 | 五星 / 4.8+ / 有声书排行 |
| **统计** | ⑦ CV | 自查 + 排行，默认只算主役 |
| | ⑧ 档案库 | 全量 + 自动筛选面板 + 手动录入（漫播那 39 部的家） |

**收听状态**六个值：在听 / 听完 / 想听 / 囤着 / 搁置 / 弃了。
它们不各占一格导航，而是 ①② 两页里的筛选条 —— 状态是给已购和收藏分类用的，
不是独立的入口。

### 几条贯穿的规则

- **听完日期**（`finished_date`）是年度汇总的唯一依据。**重刷不要改它**，
  改了那部剧会从原来那年跑到今年，旧记录就丢了。重刷记在 `rewatch_status`
  （刷过几遍）和 `rewatch_queued`（挑出来待刷）两列上。
- **听完 = 进度满格**。标成「听完」的剧，`heard_episodes` 直接等于总集数。
- **详情是居中弹窗，改完自动保存**（600ms 防抖合并，关窗前把没提交的送出去），
  没有保存按钮。只提交改过的字段，不整个对象回写。
- **列表都分页**：已购 / 收藏 / 档案库统一 `{ total, page, pages, items }`，
  默认每页 60。已购和收藏还能换排序，「自定义」那档可以直接拖卡片，
  拖完点「保存顺序」写进 `sort_order`。
  「最新 → 最旧」用的是猫耳列表的原始顺序（`bought_order` / `sub_order`，0 = 最新），
  **不是** `updated_at` —— 后者只反映最后一次同步，跟你什么时候买的没关系。
- **已购 / 收藏的状态筛选是一排档案夹标签舌**（`TabbedFolder`），点标签切筛选，
  选中的那只跟夹子体同色连成一片。空状态不出标签，免得一排全是 0。
- **档案夹颜色按标签名散列**（六色），不按它在页面排第几 —— 单夹子页面用
  nth-of-type 会永远同一个色，多夹子时几条 nth 规则还会互相覆盖。
  散列会撞色，所以同页多夹子时在调用处显式传 `tone`。
- **卡片按收听状态染色**：底部一道状态色边 + 7% 同色底。强度刻意压得很低，
  卡片墙上能看出状态分布，但不跟封面抢。
- **日程格子用半透明白**（`rgba(255,251,246,.55)`），让夹子的纸板色透上来 ——
  实色压在纸板色上会像贴了张白纸。每日更新的剧七格都占，带「每日」记号。
- **档案库的筛选只留 5 组**（收听状态 / 平台 / 类别 / 听完年份 / 评分）。
  题材、主役 CV、社团选项太多太长，侧栏塞不下 —— 按 CV 找剧去「CV」那页。
  每组标题可点，自己向上折叠，折叠状态存 localStorage。
- **不显示「落后几集」**。卡片上只有磁带进度条和「听到哪 / 共几集」。
- **更新日**从猫耳简介里解析（「⋯⋯每周五更新」「每日18点更新」），
  命中率约七成；`update_period` 字段一直是 null，别指望它。解析只在你没填时回填。
- **封面统一 1:1**，居中裁。`.cover` 里的 `img` 必须绝对定位撑满 ——
  只写 `height:100%` 的话，父元素高度由 `aspect-ratio` 推出、是「不确定高度」，
  百分比解析失败会退回 auto，竖版长海报就会把格子顶高、整排卡片对不齐。
- **分享长图**：详情页生成，canvas 手绘，高度按 repo 实际行数算。

### CV 的主役 / 配役

猫耳详情接口给的是**全体参演**，一部剧十几二十位。全算进排行就变成
「谁跑龙套最多」。所以：

- 数组前两位记为**主役**（你 Notion 里 241 部有 240 部正好写 2 位主役，
  猫耳这个数组也是主役在前，对得上）
- 其余记为**配役**，卡片不显示，详情页折叠在「全体参演」里
- CV 排行和自查**只统计标记为「听完」的剧** —— 追了没听、囤着、搁置、弃了都不算
- 默认只算主役，页面上可以切换成含全体参演
- Notion 带来的主役是你自己挑的，同步只往上加配役，不动主役

CV 数据结构是 `{ character, cv_info: { id, name, icon, group } }` ——
名字嵌在 `cv_info` 里，不在顶层。

## 数据

`data/radiotracker.db`（SQLite，WAL）。表结构和每个字段的意图见
[`server/schema.sql`](server/schema.sql)。

导入是幂等的，数据源都是文件，所以想重建随时可以：

```bash
rm -f data/radiotracker.db*
npm run import:notion && npm run import:missevan
npm run fetch:details && npm run cache:covers
```

数据库结构变更走 `scripts/migrate-*.mjs`，都是幂等的，可以重复跑：

```bash
node scripts/migrate-002-status.mjs   # 加「囤着」、拆重刷两层
node scripts/migrate-003-order.mjs   # 听完的剧拉满进度、加三个排序列
```

**当前状态**：319 部（Notion 241 + 猫耳新增 78）· 141 篇剧评 ·
660 位 CV（主役关联 618 / 配役 5652）· 279 张封面已缓存。

状态分布：听完 175 · 待整理 78 · 搁置 42 · 弃了 17 · 想听 4 · 在听 3 ·
重刷计划 2 · 重刷库 14。「囤着」是新加的状态，等你从「待整理」和
「待复核搁置」里分出来。

### 跟 Notion 对不上的地方

- **CV 排行数字更大**。Notion 的 CV relation 只填了 174 行，但「主役CV」这列
  241 行全有。这里按后者建关系，所以张福正是 34 部而不是 Notion 显示的 25 部。
- 有 1 部猫耳剧在 Notion 里没填剧ID，同步覆盖不到，需要手工补 `missevan_id`。
- 有 1 行「类别」是空的。
- 「搁置」那 42 部还是 Notion 原样。当时分不出「买了没开始」和「听了一半」，
  因为已听集数在 Notion 里基本没填（175 部听完的剧里有 150 部是空的）。
  去「待整理 → 待复核搁置」分一遍。

## 部署

现在是纯本地。要上线的话：前端 `npm run build` 出静态包；后端把 `better-sqlite3`
换成托管 Postgres（API 形状不用动）。

**同步不要上云**：猫耳导出脚本设计成在你本地浏览器跑、结果导入本地库。
如果之后要部署，建议保持「本地同步 → 只推非敏感字段」，别让登录态和购买记录进服务器。
